# SpectraLab Internal Picture Format Specification

Design document for the universal internal representation that replaces format-specific `screenData` handling. Every loaded file is converted to this format on import; every save/export converts back to the target file format.

---

## 1. Goals

- **One bitmap layout everywhere**: linear row-major (no ZX Spectrum interleaving internally)
- **Parametric dimensions**: any width x height (multiples of 8)
- **Format-agnostic editing**: all editor tools, layers, undo/redo operate on the internal format without branching on file format
- **Clean import/export boundary**: format-specific complexity lives only in converters

---

## 2. Picture Object

```js
{
  // --- Dimensions ---
  width,              // pixels, multiple of 8
  height,             // pixels, multiple of 8
  cols,               // width / 8  (byte columns)
  rows,               // height / 8 (character rows)

  // --- Content mode ---
  contentMode,        // 'pixel' | 'pattern' | 'text'

  // --- Pixel/Pattern mode fields ---
  colorMode,          // 'standard' | 'gigascreen' | 'rgb3'
  attrCellHeight,     // 8, 4, 2, or 1 (pixels per attribute cell vertically)
  planes: [           // array of planes (see section 3)
    { bitmap, attrs }
  ],

  // --- Pattern mode fields ---
  pattern,            // Uint8Array(8) dither tile, or null

  // --- Text mode fields ---
  chars,              // Uint8Array(cols * rows), character codes
  cellColors,         // Uint8Array(cols * rows), attribute bytes per cell
  font,               // Uint8Array, active font data

  // --- Optional overlays ---
  palette,            // Uint8Array(64) ULA+ GRB332 palette, or null
  border,             // Border object (section 5), or null

  // --- Metadata ---
  sourceFormat,       // original FORMAT.* constant (for export defaults)
  fileName,           // display name
}
```

Not all fields are present simultaneously. Which fields are active depends on `contentMode` and `colorMode` (see section 4).

---

## 3. Planes

A plane contains one bitmap layer and optionally one attribute layer.

```js
{
  bitmap: Uint8Array,   // cols * height bytes, linear row-major
  attrs: Uint8Array,    // cols * ceil(height / attrCellHeight) bytes, or null
}
```

**Bitmap layout** (linear row-major):
```
offset = y * cols + byteCol
bit    = 0x80 >> (x % 8)
```

Every pixel row is stored sequentially. Row 0 first, row 1 next, etc. No interleaving.

**Attribute layout** (linear row-major):
```
attrRow = floor(y / attrCellHeight)
offset  = attrRow * cols + byteCol
```

Attributes use the standard ZX Spectrum byte format: `ink[2:0] | paper[5:3] | bright[6] | flash[7]`.

### Plane count by color mode

| colorMode     | Planes | Per plane                  |
|---------------|--------|----------------------------|
| `standard`    | 1      | bitmap + attrs             |
| `gigascreen`  | 2      | bitmap + attrs (per frame) |
| `rgb3`        | 3      | bitmap only (R, G, B)      |

---

## 4. Content Modes

### `'pixel'` -- freely editable bitmap + attributes

The default mode for most formats. All editor tools (pixel, line, rect, circle, fill, brushes, selection, copy/paste) operate on bitmap and attribute data.

Active fields: `colorMode`, `attrCellHeight`, `planes[]`

### `'pattern'` -- generated bitmap, attribute-only editing

Used by .53c / .atr formats. The bitmap is procedurally generated by tiling `pattern` (8 bytes) across the full width x height. The editor restricts to attribute-only operations.

Active fields: `attrCellHeight` (always 8), `planes[]` (1 plane), `pattern`

On load: generate bitmap from pattern. On pattern change: regenerate bitmap. On export: discard bitmap, save only attrs.

### `'text'` -- character grid editing

Used by SPECSCII. The picture is a grid of character codes rendered with a font. The editor provides character-level operations.

Active fields: `chars`, `cellColors`, `font`

The `planes[]` array is not used in text mode. Rendering produces pixels on the fly from chars + font + colors.

---

## 5. Border

Border data is an optional overlay representing the ZX Spectrum screen border (BSC/BMC4 formats). It is **not** pixel data -- it encodes color stripes constrained by hardware timing.

```js
{
  top:    Uint8Array,   // 64 lines x 24 bytes = 1536
  sides:  Uint8Array,   // 192 lines x 8 bytes = 1536
  bottom: Uint8Array,   // 48 lines x 24 bytes = 1152
}
```

Total frame with border: 384 x 304 pixels. Border only exists for standard 256 x 192 pictures.

Each border byte encodes two 8-pixel color blocks:
```
bits 0-2: color 1 (0-7)
bits 3-5: color 2 (0-7)
bits 6-7: unused
```

Border has its own editor tools and its own layer channel (`layer.border` + `layer.borderMask`).

---

## 6. Layers

Each layer mirrors the picture's structure:

```js
{
  name: string,
  visible: boolean,
  mask: Uint8Array,     // 1 byte per pixel (or per cell for text mode)
                        // 1 = visible, 0 = transparent

  // pixel/pattern mode:
  planes: [
    { bitmap, attrs }  // same layout as picture planes
  ],

  // text mode:
  chars: Uint8Array,
  cellColors: Uint8Array,

  // border (if picture has border):
  border: {
    data: Uint8Array,
    mask: Uint8Array,
  },
}
```

### Compositing rules

- **Background layer** (index 0): always fully opaque, cannot be deleted or reordered below other layers. Eraser paints paper instead of making transparent.
- **Upper layers** (index 1+): composited in order. Pixel visibility determined by `layer.mask`.
- **Bitmap compositing**: for each visible pixel in upper layer, overwrite corresponding bit in output.
- **Attribute ownership**: per attribute cell, topmost visible layer with pixel content in that cell owns the attribute. Fallback: background layer.
- **Text mode compositing**: uses OVER (XOR) control codes in the SPECSCII stream.
- **Border compositing**: separate pass, per color-slot masks.

### Buffer sizes

All derived from the picture geometry:

| Buffer             | Size                                         |
|--------------------|----------------------------------------------|
| `bitmap`           | `cols * height`                              |
| `attrs`            | `cols * ceil(height / attrCellHeight)`       |
| `mask` (pixel)     | `width * height`                             |
| `mask` (text)      | `cols * rows`                                |
| `border.data`      | 4224 (fixed, BSC/BMC4 only)                  |
| `border.mask`      | 8448 (fixed, 2 slots per border byte)        |

## 7. Import Converters (file -> internal)

Each converter reads file bytes and produces a picture object.

### Bitmap deinterleaving (SCR-family formats)

ZX Spectrum SCR bitmap uses interleaved layout:
```
fileOffset = (third * 2048) + (pixelRow * 256) + (cellRow * 32) + col
where: third = y >> 6, pixelRow = y & 7, cellRow = (y >> 3) & 7
```

The converter reads each byte from the interleaved position and writes it to the linear position (`y * 32 + col`).

### Converter table

| File format  | Content mode | Color mode   | attrCellHeight | Planes | Bitmap conversion    | Notes                         |
|--------------|-------------|--------------|----------------|--------|----------------------|-------------------------------|
| SCR          | pixel       | standard     | 8              | 1      | deinterleave         |                               |
| SCR+ULA      | pixel       | standard     | 8              | 1      | deinterleave         | +palette (64 bytes)           |
| IFL          | pixel       | standard     | 2              | 1      | deinterleave         |                               |
| MLT          | pixel       | standard     | 1              | 1      | deinterleave         |                               |
| BSC          | pixel       | standard     | 8              | 1      | deinterleave         | +border                       |
| BMC4         | pixel       | standard     | 4              | 1      | deinterleave         | +border, 2 attr banks -> 1    |
| Gigascreen   | pixel       | gigascreen   | 8              | 2      | deinterleave x2      | 2 frames                      |
| RGB3         | pixel       | rgb3         | --             | 3      | deinterleave x3      | no attrs                      |
| Mono full    | pixel       | standard     | --             | 1      | deinterleave         | no attrs                      |
| Mono 2/3     | pixel       | standard     | --             | 1      | deinterleave         | no attrs, height=128          |
| Mono 1/3     | pixel       | standard     | --             | 1      | deinterleave         | no attrs, height=64           |
| 53c/ATR      | pattern     | standard     | 8              | 1      | generate from pattern| bitmap not in file             |
| SPECSCII     | text        | --           | --             | --     | parse stream         | chars + colors + font          |
| ZXP (std)    | pixel       | standard     | varies         | 1      | already linear       | may have palette               |
| ZXP (big)    | pixel       | standard     | varies         | 1      | already linear       | width/height != 256x192       |
| SNA/Z80      | pixel       | standard     | 8              | 1      | deinterleave         | extracted from snapshot memory |

### BMC4 attribute handling

BMC4 stores two 768-byte attr banks (top 4 / bottom 4 lines of each 8x8 cell). On import, interleave into one contiguous attribute array with `attrCellHeight = 4`:
```
for each cell row r (0..23):
  for each col c (0..31):
    internalAttrs[r*2 * 32 + c]     = bank1[r * 32 + c]   // top 4 lines
    internalAttrs[(r*2+1) * 32 + c] = bank2[r * 32 + c]   // bottom 4 lines
```

## 8. Export Converters (internal -> file)

Reverse of import. Each converter reads the picture object and produces file bytes.

### Bitmap interleaving

Linear position `(y, col)` -> interleaved offset using the same formula as import, but writing to file position instead of reading.

### Key conversions

| Target format | From contentMode | Conversion                                             |
|---------------|-----------------|--------------------------------------------------------|
| SCR           | pixel           | interleave bitmap, copy attrs                          |
| SCR+ULA       | pixel           | interleave bitmap, copy attrs, append palette          |
| IFL           | pixel           | interleave bitmap, copy attrs                          |
| MLT           | pixel           | interleave bitmap, copy attrs                          |
| BSC           | pixel           | interleave bitmap, copy attrs, append border           |
| BMC4          | pixel           | interleave bitmap, deinterleave attrs to 2 banks, append border |
| Gigascreen    | pixel           | interleave 2 bitmaps, copy 2 attr sets, concat frames |
| RGB3          | pixel           | interleave 3 bitmaps, concat planes                   |
| 53c/ATR       | pattern         | save attrs only (768 bytes)                            |
| SPECSCII      | text            | encode char stream with control codes                  |
| ZXP           | pixel           | write linear bitmap as text, write attrs as hex        |

## 9. Rendering

The renderer reads the internal format directly. No per-format render functions needed for the bitmap+attrs path.

### Standard rendering (1 plane)

```
for y = 0 to height-1:
  for col = 0 to cols-1:
    byte = planes[0].bitmap[y * cols + col]
    attrRow = floor(y / attrCellHeight)
    attr = planes[0].attrs[attrRow * cols + col]
    ink, paper, bright, flash = decodeAttr(attr)
    for bit = 0 to 7:
      pixel = (byte >> (7 - bit)) & 1
      color = pixel ? inkRGB : paperRGB
      drawPixel(col * 8 + bit, y, color)
```

### Gigascreen rendering

Two sub-modes:
- **Average**: render both planes, blend RGB values per pixel
- **Flicker**: alternate between plane 0 and plane 1 at 50 Hz timer

### RGB3 rendering

Combine three planes additively:
```
r = planes[0].bitmap bit -> red channel
g = planes[1].bitmap bit -> green channel
b = planes[2].bitmap bit -> blue channel
color = RGB(r * 255, g * 255, b * 255)
```

### Monochrome rendering

Standard rendering with `attrs = null`. Use fixed ink/paper colors (user-selectable, default black on white).

### Pattern rendering

Same as standard rendering. Bitmap is pre-generated from `pattern` tile.

### Text rendering

```
for row = 0 to rows-1:
  for col = 0 to cols-1:
    charCode = chars[row * cols + col]
    attr = cellColors[row * cols + col]
    glyph = font[charCode * 8 .. charCode * 8 + 7]
    render 8x8 glyph with attr colors
```

## 10. Undo/Redo

Each undo state is a deep clone of the picture's mutable data:

```js
{
  planes: deepClone(picture.planes),    // or chars+cellColors for text
  mask: cloneLayerMasks(),
  layers: deepCloneLayers(),
  activeLayerIndex,
  border: deepClone(picture.border),
}
```

Palette and pattern are not typically included (they change through separate UI actions with their own undo).

## 12. Implementation Plan

### Step 1: Define internal format and SCR round-trip

- Create `makePicture(sourceFormat, width, height, ...)` factory function
- Write `importScr(fileBytes)` -> picture object (deinterleave bitmap)
- Write `exportScr(picture)` -> file bytes (reinterleave bitmap)
- Replace `screenData` global with `currentPicture` object
- Wire up load -> import -> render and save -> export -> download
- **Test**: load .scr, verify identical display and re-export

### Step 2: Migrate remaining format converters

- Write import/export for: IFL, MLT, BSC, BMC4, Gigascreen, RGB3, Mono, 53c, SPECSCII, ULA+, ZXP
- Replace all format-specific render functions with unified renderer
- **Test**: load every format, compare rendering with before

### Step 3: Migrate the editor

- Refactor `getBitmapAddress` / `getAttributeAddress` to linear formulas
- Refactor `getPixel` / `setPixel` and all drawing tools to use picture geometry
- Refactor layer system: per-plane layer data, parametric buffer sizes
- Refactor copy/paste, selection to use `picture.width` / `picture.height`
- Refactor undo/redo to snapshot the new structure
- **Test**: all editor tools on all formats, layer operations, undo/redo

### Step 4: Big picture support

- Allow `makePicture()` with arbitrary width/height
- Canvas sizing adapts to picture dimensions (already works for BSC 384x304)
- Grid overlay uses `picture.cols` / `picture.rows`
- ZXP importer passes actual width/height
- **Test**: load big .zxp, view and edit

### Step 5: Project file migration

- Implement .slp v4 save/load
- Drop v3 compatibility (or add one-way v3 -> v4 migration if desired)
- **Test**: save/load projects with layers, all formats, big pictures
